**Failed check:** C3 — the behaviour on the task's own trigger cannot be compared with the requirements, because the requirements do not state the trigger.
T-012's two central criteria fire when "the dictionary offers nothing that matches" (FLOW-022 (1)) and when "nothing in the dictionary matches" (FLOW-023 (6)); DOM-009 (2) stores free text for an ingredient typed "because no entry matched". `spec/` states neither (1) what the ingredient field's search counts as a match — whole label or one word, case, `ё`/`е`, word forms, the labels of one language or both; L10N-007 decides these for a reader's text query over recipes and not for the dictionary — nor (2) whether "nothing matches" means that the search returned no entry, so that free text is offered only on an empty list, or that no entry is the ingredient the author means, so that free text is offered beside the entries. For `кокосовое молоко` against a dictionary holding `молоко`, the first reading leaves the author the entry `молоко` with a qualifier, found by a filter on `молоко` permanently once published, where FLOW-023 (3) calls the qualifier a last resort and FLOW-022's source says a missing entry never blocks authoring; the second offers free text where an entry does match, which the conditional wording of FLOW-022, FLOW-023 (6) and DOM-009 (2) does not describe. Whoever builds the field would make that product decision, and gate 2 could not tell a right one from a wrong one (TEAM-008). Class: omission (item 1), ambiguity (item 2). No replacement is stated (PO-006). Route: the user runs `/req-forge` on SD-006; the task returns to gate 1 when FLOW-022, FLOW-023 or DOM-009 changes. This is not a return (TL-011).
