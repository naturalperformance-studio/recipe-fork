(1) The entry's note (backlog.md line 431) ships a dictionary snapshot so that FLOW-001 (1) holds on a clean installation with no connection. The snapshot is as old as the last release (ADR `docs/architecture/decisions/20260928-dictionaries-ship-with-the-application.md`, Consequences). Gate 2 reads FLOW-001 (1)'s "exactly as they are with a connection" as comparing the same held copy offline and online. It does not read it as requiring a clean offline installation to match the server's current dictionaries. The offline-to-current match is FLOW-001 (6), which is carried by T-004. (2) FLOW-002 (3, 4) name the states `private`, `rejected`, `pending`, `link_shared`, `published`, `reported_hidden` and `removed`. A device reaches none of these in wave 1, because nothing is sent. Gate 2 accepts a test that seeds a recipe in each state as evidence of what the editor allows, as it did at the previous gate 1.
**Spec defect written:** SD-038 in docs/product/spec-defects.md

**Failed check:** C3 — different trigger, and the task cannot repair it.
FLOW-042 (4) is the only criterion the entry carries for the editor's entry point. Its
trigger is "Given an account that has written nothing, when it opens the own-recipes view".
T-008 is in wave 1, and wave 1 has no account on the device (backlog.md line 34; T-007's note, line 362:
"Accounts, their books and the switch between them are wave 1b's"). T-008's own note
(line 431) creates the new recipe "in the active book — the pool in this wave". Under
AUTH-026 the pool is "one pool that belongs to no account" (spec/45-auth/25-accounts-on-a-device.md
line 119). So the behaviour T-008 builds is the empty own-recipes view of the pool, its
offer, and the editor opened from it. FLOW-042's statement covers that view: "writing a recipe
in the own-recipes view". FLOW-034 (7) (spec/70-flows/50-browsing.md line 85) places the pool
in that view when no account is active. No criterion observes it, though. The criterion the entry
carries names an account, and on T-008's branch nobody can set that Given up. At gate 2, a test with no account
would not evidence FLOW-042 (4). A test that seeds an account's empty book would evidence (4), but it would
leave the pool's empty view, which is what wave 1 actually builds, with no criterion behind it. This is where
T-008 differs from T-007, accepted today (docs/product/verdicts/20260928-T-007-gate1.md). T-007's account-worded
criteria are backed by FLOW-034 (7), which observes the same view for the pool. FLOW-042 has no counterpart
of that kind.

This is not a rejection, because the task has no correct form to return in. C5
requires FLOW-042 (4) to be copied word for word. If (4) is moved to wave 1b, wave 1's only
way into the editor has a statement behind it but no criterion, and gate 2 could not
walk it. Deciding whether the pool's empty view is observed by (4) or by a criterion of its own is a product
decision. It is recorded as SD-038 for `/req-forge`, and T-008 does not settle it by choosing a reading.
Counterfactual: T-008 would pass if "an account that has written nothing" could be read to
include a person with no account whose pool is empty. AUTH-026's "belongs to no account"
and FLOW-034 (7), rewritten on 2026-09-28 (0745e70) as a separate criterion for the
no-account case, both rule that reading out.
