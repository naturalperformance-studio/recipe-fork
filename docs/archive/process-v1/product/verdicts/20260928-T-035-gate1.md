C3 stops on what the field holds. DOM-017 decides by the value an entry is read as, and
each criterion names the entry as a literal typed string. Two parts of that reading are
not stated.
- *Decimal mark and grouping.* L10N-009 states how a number is displayed in each language
  and says nothing on how a typed one is read. DOM-017's own examples need the Russian reading.
  `1,5 кг` is held only if the comma is a decimal mark. `1,2345 кг` is refused only because
  it reads as 1234.5 g. L10N-001 (1), which this task carries, puts the same field in the English
  interface, and there the same keystrokes give different values. `1,500 kg` is 1500 kg under
  English grouping and 1.5 kg under a decimal comma, and both values are on the grid. `1,2345 kg`
  is refused under a decimal comma, and is held as 12 345 kg if the comma is taken as unchecked
  grouping. A point typed in the Russian interface (`1.5 кг`) is read one way or the other with
  nothing to choose between them.
- *Decimal entry of a value the grid writes as a fraction.* The statement ("only a value
  above zero that the rounding grid of its unit type displays") and criterion (4) ("a
  number however large that lies on the grid") hold `2,5 шт` of a divisible ingredient,
  because 2.5 is the value the grid shows as 2½. The table's written forms ("a whole number
  followed by ½"), SCALE-014 (5), and the pattern of criteria (1) and (3) point the other way.
  In (1) and (3) each "of a … ingredient" qualifies only the item before it. Read like that,
  criterion (2)'s "`2,5 шт` or `½ шт` of an indivisible ingredient" refuses `2,5 шт` whatever
  the divisibility. Under the first reading, refusing it fails (4). Under the second, holding it
  fails (2).
The developer would settle both in the parser. Gate 2 could not mark a test of
`1,500 kg`, `1.5 кг` or a divisible `2,5 шт` as met or not met (TEAM-008).

The reading under which the task would pass has two parts. L10N-009 reaches entry because the
field reads a number the way it would display it. The statement's "value" settles the second
point. That reading does not hold. L10N-009's statement, criteria and verification are all about
display. The Russian decimal comma of DOM-017's examples and English grouping cannot both be
read "the way the interface writes them" for the same keystrokes, unless someone decides that the
field reads by interface language. That decision is not in `spec/`. Choosing it here would write
the requirement instead of reading it.

The verdict is not `rejected`. The entry copies the criteria verbatim, as C5 requires, and a
corrected task would read the same.
