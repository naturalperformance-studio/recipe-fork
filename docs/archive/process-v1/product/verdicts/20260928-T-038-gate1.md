(`spec/70-flows/10-offline-and-sync.md:359`). Commit 0745e70 inserted a new first criterion
("Given a device holding changes not sent to a recipe…"). Since then FLOW-008 (2) reads
"…the server's version keeps the recipe's identity and device B's version becomes a
`private` fork naming it as parent." It says nothing about telling the owner. The notice is
now FLOW-008 (3). The "Changed 2026-09-28" note (line 375) also still calls it "criterion 2".
The class is incorrect fact, a stale cross-reference. It leaves an ambiguity in what (6)
obliges.
The counterfactual is the reading under which the entry passes: the reference is residue
of the renumbering and plainly means (3). The statement and the 2026-09-27 correction
support that reading. But gate 2 could then mark (6) met only by putting "3" where the
criterion says "2", and that choice would be a rewording of the requirement (TEAM-008).
Rejecting the task would not help either. C5 obliges it to copy these words, so it would
come back unchanged and spend one of its two returns on a defect that is not its own
(TL-011). The same stance was taken on a stale antecedent in SD-036.
