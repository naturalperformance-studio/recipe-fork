**Where the behaviour is produced.** In `core/src/main/kotlin/app/recipefork/core/scaling/Scaling.kt`, `Scaling.display` multiplies the authored quantity by an exact rational factor. At a factor of 1 it returns the authored value unchanged and not derived. At any other factor it takes the exact product to the grid value from `RoundingGrid.nearest`, and it marks the result as derived. `ScaleFactor.forServings` makes the factor the requested count over the authored count, with no ceiling. `RoundingGrid.kt` holds the four grids of the section index. For `exact`, the grid is whole base units below 1 000 000 g or ml and whole thousands at and above. The nearest grid value is chosen, a tie goes to the larger, and the floor applies where the nearest value would be below it.

**Sweep for observable behaviour no criterion asked for.** None of the diff is visible to a user, because no screen, string, stored field or control is added. Three things were checked because each could surface later:
- The derived flag and the direction of rounding (`Rounding.UP/DOWN/NONE`). These are SCALE-004's marker and SCALE-005's "mark it as rounded up". Both are computed and neither is rendered. Rendering them is T-019's.
- `forServings` refuses a requested count below ¼. SCALE-010's statement sets that floor.
- At a factor of 1, an off-grid authored value is returned as written. That is SCALE-001 (4) and DOM-017 (7), and no author can enter such a value before wave 4 (DOM-018).

None of the three is an addition.

**Counterfactual.** Any of the following would have made this `rejected`:
- a scaled value computed from a rounded one;
- a zero or sub-floor line at some factor;
- a tie resolved downward;
- an authored value altered or marked as derived at the authored count;
- a refusal at a large count;
- a criterion whose only test asserted an internal call instead of the displayed value;
- a user-visible element nobody specified.

None was found. Each criterion has a test that asserts the displayed value itself.
