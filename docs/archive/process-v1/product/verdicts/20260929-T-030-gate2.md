**Where the behaviour is produced.** Both behaviours are in `core/src/main/kotlin/app/recipefork/core/scaling/ScaledRecipe.kt`.
- The new `requestServings(servings)` returns the recipe at the requested count with an empty fixing list. So the factor is the requested count's (SCALE-001), no line is fixed, no shortfall can arise, and `servingCount` is the requested value, not approximate.
- `release(ingredient)` was already there. It removes one fixing and keeps `requestedServings`. A fixing never changes `requestedServings`, and a change of count clears every fixing. So when the last fixing is released, the count shown is the one in force before the first fixing, and not the approximate count shown during the fixing.
