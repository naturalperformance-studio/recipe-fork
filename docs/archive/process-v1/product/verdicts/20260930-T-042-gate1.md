**Failed check:** C3 — on the task's own trigger, a sending that already made a fork, sent again after the server's content has become the same as it, is given two different outcomes by the requirements the task carries.
The sequence, reachable with two devices on one account:
1. The server holds content Y at r2.
2. Device B, made from r1, sends X, and the server makes the fork F (FLOW-008 (2)).
3. The answer to that sending is lost.
4. Device A sends the same edit X, and the server's copy becomes X.
5. Device B sends the same sending again.

The criteria this entry copies then say two things:
- FLOW-008 (7): "Given a sending whose content is the same as the content the server holds, when it arrives, then it is not a divergence whatever version it was made from, and FLOW-066 governs it." FLOW-066 (2): "…then the server's copy is unchanged, no fork is created and device B marks the recipe as sent." FLOW-066's statement: "shall mark the recipe on the device as sent … and shall show on the device the state the server holds it in." The answer is "sent", and nobody is told of F.
- FLOW-066 (4): "Given a divergent sending that made a fork (FLOW-008) whose answer never reached the device, when the same sending arrives again, then the server answers with the fork it already created and creates no second one, and the owner is told of that fork once, as FLOW-008 (3) states." FLOW-008's statement says the system "shall tell the owner that it did so". The answer is fork F, and a notice follows.

Both Givens are met by the same arrival, and their Thens cannot both hold. The developer has to choose which check the server makes first, and that choice decides what the owner sees. Gate 2 would then have no way to call the result right or wrong (TEAM-008). This is not `rejected`. The entry describes neither more nor less than the requirements, and C5 obliges it to copy both criteria as they stand, so a returned entry would come back identical. The reading under which the task would pass is that one criterion's Given silently excludes the other's case. No word in either one says so, and choosing which criterion gives way is the product decision. Class: inconsistency. The route is `/req-forge`.
