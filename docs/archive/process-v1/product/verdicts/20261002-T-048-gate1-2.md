**Failed check:** C3 — the task describes less than FLOW-067 now states.
spec/ @ 71ea18a widened FLOW-067's statement ("or, when FLOW-066 answered it by writing nothing, the revision the server held at that moment") and added two criteria, both server behaviour:
- FLOW-067 (3): "Given an unanswered sending whose content was the same as the server's, so that FLOW-066 wrote nothing, when the owner edits the recipe and sends it while no other device has changed it since, then the sending is made from the revision the server held when that sending arrived: the server's copy is replaced, no fork is created and no notice is shown — the device took the server's changes, and the edit lies on top of them."
- FLOW-067 (4): "Given that revision held in `pending`, `link_shared` or `published`, when the owner's edit is sent, then nothing is written to it and the edit becomes a `private` fork as FLOW-008 (4) states, because that recipe cannot change."

Neither is in the entry's criteria, and neither is in its carried-elsewhere line. The entry's design Note still records, for each stored sending, "the revision it wrote, or the fork it created". A sending FLOW-066 answered writes no revision, so under that design it leaves nothing and the next edit is answered as in SD-046's rejected reading, a fork with a notice. That is the outcome FLOW-067 (3) now excludes.

The new criteria were inserted at (3) and (4), so the old (3)–(7) are now (5)–(9). The entry's Notes cite the old numbers: "FLOW-067 (5)" for the fork, "(3)" for a sending not stored, "(4)" for two in a row, "(6)" observed here alone, "(7)" for FLOW-059 (14)'s case, and "FLOW-067 (1–5, 7) → T-049". Under the current text each of these names a different criterion. That is not a separate check. It is recorded so that the re-cut corrects it, because the developer agent reads the numbers against its slice of `spec/` (TL-008).

Counterfactual: the entry would pass if FLOW-067 (3) and (4) were carried here (or named as carried elsewhere at the server), the design recorded the revision held when FLOW-066 wrote nothing, and the numbers matched the current text. The seven criteria it does copy are still word for word in `spec/`. The entry is short of the requirement; nothing in it is wrong.
