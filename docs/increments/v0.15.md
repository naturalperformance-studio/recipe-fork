## Goal
An ingredient is found by the word you actually write (картошка, манка, томат, icing sugar), and search stops landing on look-alike entries that are not what you meant.

## What exists at the start
On `develop` @ c34a7fa (v0.14 shipped). 2 531 live ingredient entries and 293 tags generated from `dictionary/*.tsv` by `scripts/dictionary-build.sh`. Core search (`core/search/WordPrefix.kt`) folds case, ё/е and Latin diacritics and has a light inflection reducer; the editor offers through `app/dictionary/IngredientOffer.kt`, the book searches through `app/recipe/BookSearch.kt`. `RecipeCorpusTest` reports 99.2 % but counts a "shared main word" as found; the honest rate is about 94 %.

## Demo scenarios
1. In the editor type «картошка», «манка», «томат», "icing sugar", "confectioners' sugar" → the right entry is offered with the matched word beside it in a muted style («картофель · картошка»).
2. Search the book for «картошка» → recipes holding картофель are found; the ingredient filter works as before.
3. Type «сыр моцарелла», «куриные крылья», «овсянка», "bay leaves", "roma tomatoes", "swiss cheese", "chicken broth" → the intended entry comes first, not адыгейский сыр, куриные бёдра or bay boletes.
4. Search the book for "buttermilk", «лимонад», "pepperoni" → recipes with butter, lemon or pepper no longer come up.
5. Type «яйца», "eggs", "onions" → the plain entry (яйцо, onion) comes first, before its kinds.
6. Type «пармиджано» → one entry, «пармезан (пармиджано реджано)»; the duplicate is gone.

## Out of scope
- Filling synonyms at large: only the corpus misses (картошка, манка, курдючный жир, confectioners' sugar, hamburger buns) and томат are seeded, plus whatever T-131 needs to reach the corpus threshold.
- Synonyms on tags.
- Moving existing recipes' free-text ingredients onto entries.
- The server's dictionary store and routes carrying synonyms (serverless is the product today).
- Theme, dark theme and any interface polish — v0.16 (roadmap F1).

### T-130 — Honest search
**Status:** done
**Serves:** 3, 4, 5, 6 · **Core:** yes · **Depends on:** —
**Expected files:** `core/src/main/.../search/WordPrefix.kt`, `core/src/test/.../search/WordPrefixTest.kt`; `app/src/test/.../dictionary/RecipeCorpusTest.kt` and its corpus file; `app/dictionary/IngredientOffer.kt` only where ranking needs it; `IngredientOfferTest.kt`.
**Criteria:**
- The corpus test names the intended entry for every line and counts a line as found only when that entry is among the first five offers; it prints every miss and every wrong landing; its threshold stays 95 % per language (it may fail on this branch — T-131 fills the dictionary to meet it; record the honest rate in the test output and mark the threshold assertion so T-131 enables it).
- English "-ves" plurals reduce correctly (leaves → leaf, halves → half, loaves → loaf); "greens" stays "greens".
- The label-stem rule applies to Cyrillic only and only when the remaining suffix is short (at most 3 letters): "buttermilk", "watermelon", "pepperoni" no longer match butter, water, pepper; «лимонад» and «сахарин» no longer match лимон and sugars; «лука», «моркови», «сахара» still match.
- A plural or inflected form of a label (яйца, eggs, onions) counts as the exact match, so the plain entry is offered first, before its leaves.
- The same rules hold in the book's text search (it uses the same core code).
- The v0.12 bench still holds (offer per keystroke ≤ 50 ms).
**Notes:** Corpus lines now carry the intended id(s) or `gap`; a name counts only when that id is in the first five offers (also retried cut to its main word, still requiring the intended id). Honest rate 93.9 % RU / 94.0 % EN (as written only: 92.0 / 87.1), floors at 93 % active, 95 % thresholds @Ignore'd for T-131. Review round 1: pass, every rule confirmed by mutation. Nits carried to T-131: a singular typed against a plural label is never exact («грецкий орех» lands on варенье); «морковка» drops морковь behind its five kinds; parent words count in the offer only, not in the book search. Merged.
