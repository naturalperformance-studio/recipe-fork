# v0.20 — Colours in one file, a dark theme, a settings screen
**Status:** active
**Planned:** 2026-10-04 · **Shipped:** —

Goal, scenarios and out-of-scope approved by the user on 2026-10-04 (with v0.19 and v0.21): F1 of `serverless-roadmap.md` plus audit 28 of `ux-roadmap.md`. The user decided on 2026-10-03: one theme file in the repository; the app offers only the choice of theme (light / dark / as on the device).

## Goal
The app's colours change by editing one theme file, without touching Kotlin; there is a dark theme; the book's settings live on one screen.

## Demo scenarios
1. Changing a colour in the theme file and rebuilding changes it across the whole app; a short note says where the file is and how to edit it.
2. The book opens a "Settings" screen that shows current values: language, usual servings, theme, drag side, storage.
3. With "Dark", everything is readable and the status-bar icons are visible; ContrastTest covers both themes.
4. With "As on the device", the app follows the system's switch.

## Out of scope
- User-made themes inside the app (`later.md`).
- Replacing hand-built controls and motion (v0.21).

### T-154 — One theme file, light and dark schemes
**Status:** done
**Serves:** 1, 3 · **Core:** no · **Depends on:** —
**Expected files:** `res/values/app_theme.xml` (new), `ui/AppTheme.kt`, `MainActivity.kt` (system bars), `ui/ContrastTest` and any test that reads `AppColors`, screens only where a colour does not come from `MaterialTheme`.
**Criteria:**
- Every Material 3 colour role of a light and a dark scheme is a named colour resource in `app_theme.xml` (ADR 20261004); `AppTheme` builds both schemes from it; the light scheme's values equal today's colours, so nothing changes visibly in light.
- The shape scale and the main type sizes come from `dimen` values in the same file.
- `AppTheme(dark = true)` renders the book, the card and the editor readable: ContrastTest checks every pair it lists in both schemes; the system bars' icons are dark on the light scheme and light on the dark one.
- A test proves a changed resource value reaches the screen (e.g. a test resource override of `theme_light_primary` shows on a primary button).
**Notes:** passed review first time. Nits dropped: the clip play mark's pair missing from ContrastTest; the changed-value test fakes Resources rather than a test resource. The window theme's light first frame is carried into T-156.
