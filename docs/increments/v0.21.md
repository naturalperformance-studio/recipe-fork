# v0.21 — Everything from M3 components, with motion
**Status:** active
**Planned:** 2026-10-04 · **Shipped:** —

Goal, scenarios and out-of-scope approved by the user on 2026-10-04 (with v0.19 and v0.20): audit 31 and 32 of `ux-roadmap.md` and the parts it left until after the theme (26 error tone, 29 type scale, 30 tonal surface, the colour parts of 7 and 8).

## Goal
Every element of the interface takes its colour, shape and type from the theme, and what appears or disappears does so with motion.

## Demo scenarios
1. Buttons and links in the book, the card and the editor are M3 components; changing a shape in the theme file shows everywhere.
2. Panels and blocks appear and disappear smoothly; with the system's animations off, nothing moves.
3. Step text takes its size from the theme's type scale; destructive actions use the error tone; the ingredient list sits on a tonal surface; timer colours come from the theme.

## Out of scope
- Handing the build to people (own signing key, icon, backup — `later.md`).
- A step-by-step cooking mode (rejected by ADR 20260921).

## Tasks
Order: T-157 and T-158 start together; T-159 after both (it touches the same screens).

What exists at the start (develop after v0.20): colours, corners and type sizes come from `res/values/app_theme.xml`; no screen draws a colour outside the scheme; no `RoundedCornerShape` outside `ui/AppTheme.kt` (icon buttons clip to `CircleShape`, as M3's do). Hand-built controls left: `ActionText` (5 uses in the editor), `UnitField` (the editor's unit box), `StepAction` (the card's step glyph buttons), `FixAction` (the card's fixing control). Motion: 4 uses of `AnimatedVisibility`/`animateContentSize`/`animateItem` in the whole app.

Standing note for every task: load the `android-m3-ui` skill and follow `docs/architecture/ui-conventions.md`; interface strings in English and Russian; tests wait for conditions, never on timing; touch targets ≥ 48 dp (56 dp on the card) and ContrastTest stays green in both schemes; existing behaviour covered by tests stays (adapt tests' structure, not their meaning); Material 3 components from the version catalog, no new libraries. Gradle: the shared `~/.gradle`, never a per-run `GRADLE_USER_HOME`; no `./gradlew --stop` from agents. Tests that tap a control scroll to it first.

### T-157 — The editor's controls are M3 components
**Status:** running
**Serves:** 1, 3 · **Core:** no · **Depends on:** —
**Expected files:** `editor/EditorScreen.kt` (`ActionText` removed), `editor/IngredientsSection.kt` (`UnitField`, the row menu), `editor/StepsSection.kt`, `editor/TagsAndLanguage.kt`, `media/SourceSheet.kt` (the remove item's tone), tests.
**Criteria:**
- Every `ActionText` use becomes an M3 button (`TextButton` / `OutlinedButton` / `FilledTonalButton` by weight); `ActionText` is gone.
- The unit field is an M3 `ExposedDropdownMenuBox` with a read-only `OutlinedTextField` (or the M3 equivalent), keeping the Next chain into its menu and every unit behaviour.
- Destructive items in the editor's menus and sheets (remove a row, a step, the cover, a photo or clip) use the error colour.
- A test proves a changed corner size in the theme reaches an editor button (the shape comes from `MaterialTheme.shapes`).

### T-158 — The card's controls and type come from the theme
**Status:** running
**Serves:** 1, 3 · **Core:** no · **Depends on:** —
**Expected files:** `card/CardScreen.kt` (`StepAction`, the ⋮ Delete item's tone), `card/FixAmount.kt` (`FixAction`), `card/StepsList.kt` / `card/StepText.kt` (step type), `card/IngredientsList.kt` (the list's surface), `timer/` only for colours, tests.
**Criteria:**

- The ingredient list sits on a tonal surface (`surfaceContainerLow` or similar) from the scheme; the card's Delete/Remove menu item uses the error colour; running timers' colours are scheme roles.

### T-159 — Things appear and go with motion
**Status:** todo
**Serves:** 2 · **Core:** no · **Depends on:** T-157, T-158
