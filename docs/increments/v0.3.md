# v0.3 — Writing a real recipe comfortably
**Status:** shipped
**Planned:** 2026-10-02 · **Shipped:** 2026-10-02

Goal, scenarios and out-of-scope below were approved by the user on 2026-10-02.

## Goal
Write a real recipe without friction: quantities inside the steps' text recalculate with the servings, steps and ingredients go anywhere and can be reordered, and a recipe no longer wanted can be deleted.

## What exists at the start
On `develop` @ 1765f47 (v0.2 shipped): the editor appends steps and ingredient rows at the end and deletes them; steps carry keys (`RecipeEditor.stepKey`) so what the screen holds for a step stays with it, ingredient rows do not (a v0.1 known issue). The model already has `Step.ingredientReferences` (`IngredientReference(ingredientPosition, textOffset)`), stored in the book's `step_reference` table and carried by a fork; `RecipeEditor.removeIngredient` already drops and renumbers references; nothing writes or shows a reference. `TimerName.of(step)` derives a timer's name from the step's plain text. The card's steps are `card/StepsList.kt`; running timers are keyed by book, recipe and step position (`timer/RunningTimers.kt`) and a stale one is dropped when its card opens (`RecipeTimers.dropStale`). The book has no way to delete a recipe.

## Demo scenarios
1. In the editor, in a step "Всыпьте … муки", use the step's "Insert ingredient" control (or type `@`) and pick "Мука" → "200 г" appears in the step's text → on the card the step reads "Всыпьте 200 г муки".
2. On the card, go from 4 to 8 servings → the step reads "400 г", exactly what the ingredient list shows, with the same rounding arrow where the list has one; a reference to a "to taste" ingredient reads "по вкусу".
3. Insert a step between the second and the third; move the fourth above the second by dragging (or by the up/down actions); the same with ingredients → the order is as set, timers and references stay with their steps and ingredients, and the card shows the new order.
4. Delete an ingredient that a step references → the reference leaves the step, the rest of the step's text stays.
5. On a recipe's entry in the book choose "Delete" → a statement says it goes at once and cannot be brought back → "Cancel" changes nothing; confirming removes the recipe; if the book is now empty, it offers to write a recipe.

## Out of scope
- The usual serving count and a count held for the session (FLOW-017); restoring the scroll position (FLOW-012).
- Photos and video (FLOW-026, `90-media`).
- Recipe files (FLOW-063, FLOW-064).
- The editor's minimum/maximum warnings (FLOW-028) and its "what a fork carries" marking (FLOW-030).
- Search and filters in the recipe book (FLOW-035).
- Server, sending, publication, catalogue, ratings.
- Accessibility and localisation sweeps; ordinary good practice inside each task is enough (every new action has a 48 dp target and a text alternative naming its row).

### T-068 — Insert and move steps and ingredients
**Status:** done
**Serves:** scenario 3 · **Core:** yes · **Depends on:** —
**Expected files:** `app/src/main/kotlin/app/recipefork/app/editor/RecipeEditor.kt`, `StepsSection.kt`, `IngredientsSection.kt` (and `EditorScreen.kt` if needed); `strings_editor.xml` (both); tests under `app/src/test/kotlin/app/recipefork/app/editor/`.
**Criteria:**
- Every editable step and every editable ingredient row carries a row menu (48 dp target, text alternative naming the row, e.g. "Step 3 actions") with Insert above, Insert below, Move up and Move down; the first row has no Move up, the last no Move down (FLOW-025 (1, 2, 6), A11Y-006).
- Inserting puts a new empty step, or a new row exactly like an appended one, at that position; the rows after it move down (FLOW-025 (1)).
- Moving changes the order and nothing else: no step's text, timer or timer name changes, no row's content changes (FLOW-025 (2, 4)).
- Every step's reference still resolves to the same ingredient after ingredients are inserted, moved or deleted, and references move with their step (DOM-007, FLOW-025 (3, 5)); tested on the editor's model with references put into the recipe directly.

- A frozen recipe shows no row menu.
**Notes:** Review round 1 passed the mutation check on every criterion and found one `must`: the row keys lived only in the editor, so after a move or insert and an activity recreation a step's timer fields came back on another step and the next edit wrote a wrong duration. Re-review passed; merged. The re-review's nit — no test inserts a row after a restore — is folded into T-070.

### T-074 — Inserting a reference keeps typing going and spaces itself
**Status:** done
**Serves:** scenario 1 · **Core:** yes · **Depends on:** —
**Expected files:** `app/src/main/kotlin/app/recipefork/app/editor/StepTextField.kt`, `StepsSection.kt` (the insert control and the offer); `core/.../recipe/StepText.kt` only if the spacing rule belongs there; tests under `app/src/test/kotlin/app/recipefork/app/editor/` and `core/src/test/...`. **Criteria:**

- Removing a reference leaves single spacing: "Всыпьте 200 г муки" → "Всыпьте муки", not two spaces; a reference removed at the start or end of the text takes its neighbouring space with it; before punctuation, the space before the reference goes ("добавьте 200 г." → "добавьте.").
- The added and removed spaces are ordinary typed text, saved like any other; every T-070 keyboard test still passes.
**Notes:** From the demo feedback of 2026-10-02. The spacing rule lives in `:core` (`ReferenceSpacing`); deleting an ingredient closes up its references' spaces too.
