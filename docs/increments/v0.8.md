# v0.8 — A book you find things in, and a camera that shoots the whole scene
**Status:** shipped
**Planned:** 2026-10-03 · **Shipped:** 2026-10-03

Goal, scenarios and out-of-scope below were approved by the user on 2026-10-03.

## Goal
A recipe is found in the book in seconds, the book's entries have a tidy menu, and the camera shoots the whole scene with the crop chosen after the shot — and an export always carries the recipe as written.

## What exists at the start
On `develop` @ 9f4e42b (v0.7 shipped). The book (`library/LibraryScreen.kt`) has two views — own recipes and marked (found) ones — each entry with a cover thumbnail and, in the serverless build, a line of text buttons under it (Export, Delete / Remove). There is no search, filter or ordering choice; own recipes are listed newest first. The camera (`media/camera/*`, CameraX) shows a viewfinder framed 4:3 (on the user's phone it framed portrait) and stores that frame; gallery photos are attached as picked. The defect found at the v0.7 demo is T-092.

## Demo scenarios
0. Export always carries the recipe as written, whatever the card shows (T-092).
1. A recipe's entry in the book has ⋮ at its end with "Export" and "Delete" ("Remove" for a found recipe); no buttons under the entry; in both views.
2. A search at the top of a view: "кур" finds "Курица с рисом" and a recipe with chicken only among its ingredients; case and ё/е do not matter; it searches the open view only.
3. A filter by a dictionary ingredient keeps the recipes holding it, the most per serving first; a filter by tags; the list ordered newest first, oldest first or by title; each view keeps its own choice.
4. "Take a photo" opens the camera full-screen; after the shot a crop opens — a 4:3 frame you can move and zoom; "Done" attaches, "Retake" goes back to the camera; a gallery photo goes through the same crop.

## Out of scope
- A left-handed drag column; video; the server.

## Tasks
Order: T-092 runs; T-093 (camera) and T-094 (entry menu) start now; T-095 follows T-094; T-096 follows T-095.

Standing note for every task: leaving the editor shows the card, and tests reach the book through `compose.backThroughTheCard()`. UI tests use the `junit4.v2` Compose rules, wait for conditions (`PATIENCE_MS`), never on timing, and must pass in a full-suite run, not only alone. The hand-test build is the minified serverless release; a task that adds classes reached by reflection runs `scripts/device-test-release.sh`.

### T-092 — Export carries the recipe as written, never a recalculation
**Status:** done
**Serves:** the v0.7 demo's defect · **Core:** yes · **Depends on:** —
**Expected files:** wherever the cause is — `card/*` (fixing an amount), `recipe/RecipeRepository.kt`, `file/RecipeExport.kt`, `core/.../file/*`; tests under `app/src/test/kotlin/app/recipefork/app/file/`, `.../card/`.
**Criteria:**
- Reproduce first, as the user did: open a recipe's card, fix an ingredient's amount (and, separately, change the serving count), change nothing in the recipe itself, export it → today the file carries recalculated quantities. Find the cause and fix it there.
- Whatever is shown on the card — a count, a fixing, the usual count — the exported file carries the recipe exactly as authored: its serving count and every ingredient's authored quantity; a test exports after each of those and compares the document with the stored recipe.
- Nothing the card's scaling does is ever written to the book: after fixing, changing the count and leaving, the book file holds the recipe unchanged (reopened from disk).
**Notes:** Cause: the file was always written from the stored recipe; but checking it on one phone means deleting the recipe and opening its file, and the re-imported recipe (same identity) opened at the deleted card's count and fixing, which T-091 held per identity for the session. Fix: an import forgets what the session held for the arriving identity (`LibrarySession.showImported`, from both import routes). Reproduced by a test that failed before; passed review with mutations on the first round; merged. Nit left: no direct test that a recipe already in the book keeps its held state on a refused re-import.

### T-095 — Search and order in the book
**Status:** done
**Serves:** scenarios 2, 3 · **Core:** yes · **Depends on:** T-094
**Expected files:** `library/*` (a search field and an order choice per view), `book/BookDatabase.kt` (queries), `core/` if matching rules belong there; strings (both); tests under `.../library/` and `core/src/test/...`.
**Criteria:**
- Each view has a search field; a query matches a recipe whose title, or one of whose ingredients' names (dictionary labels in both languages, or free text), has a word beginning with the query's words; case and ё/е are ignored; the query searches the open view only (FLOW-035 (4)).
- Each view offers an order — newest first, oldest first, by title — kept separately per view for the session (FLOW-035 (3)).
- An empty result says so and offers to clear the search.
- With a few hundred recipes the list updates as one types without visible lag (measured on the JVM: the query returns within a budget).
**Notes:** Before review the lead changed the match so a query's words may stand in different places of a recipe ("плов кур"). Passed review with the mutation check on the first round (every criterion caught; the editor's ingredient offer, now sharing the matcher, unchanged); merged. Nits taken into T-096: an index built while the dictionary could not be read is cached without labels; a list restored after process death scrolls to the top. Left: Latin diacritics are not folded; the collation locale and "latest query wins" are not pinned by tests.

### T-096 — Filters by ingredient and tag
**Status:** done
**Serves:** scenario 3 · **Core:** yes · **Depends on:** T-095
**Expected files:** `library/*`, `book/BookDatabase.kt`, `core/.../scaling/*` (quantity per serving for ordering), strings (both); tests under `.../library/`, `core/src/test/...`.
**Criteria:**
- A filter by a dictionary ingredient (picked as in the editor's name field) keeps the recipes holding that entry; a free-text row matches no entry filter (CAT-006); results order by comparable quantity per serving, most first (CAT-002, CAT-007), recipes without a comparable quantity last.
- A filter by one or more tags keeps recipes carrying all of them.
- Filters combine with the search and the order; each view keeps its own for the session; one control clears them.
- (From T-095's review) An index built while the dictionary could not be read is not cached, so the next query reads it again; a list restored after process death keeps its scroll position instead of jumping to the top (scroll to the top only when the query, order or filters actually change).
**Notes:** Passed review with the mutation check on the first round (every criterion caught; a 500-recipe bench with search and both filters ran at ~1.6 ms); merged; the release smoke test re-run green. Nits left: no test that a readable dictionary is not re-read per keystroke, nor of a cyclic parent map, nor of t→g / m³→ml; with the dictionary unreadable an ingredient filter quietly matches the entry alone.

### T-093 — The camera full-screen, the crop after the shot
**Status:** done
**Serves:** scenario 4 · **Core:** no · **Depends on:** —
**Expected files:** `media/camera/*`, a new `media/crop/*`, `media/PhotoSources.kt` (routing camera and gallery through the crop); `strings_media.xml` (both); tests under `app/src/test/kotlin/app/recipefork/app/media/`, `app/src/androidTest/` for the real camera.
**Criteria:**
- The camera's viewfinder fills the screen (the full sensor frame, no 4:3 mask); the shutter takes the full frame.
- After the shot a crop screen opens: a 4:3 landscape frame over the photo that can be moved and zoomed (pinch and drag; never smaller than 1600 px wide in source pixels when the source allows, never outside the photo); "Done" attaches the cropped image through `PhotoAttaching`; "Retake" returns to the camera; back cancels with nothing attached.
- A gallery photo goes through the same crop before it is attached.
- The orientation a photo was taken in is respected (a photo taken upside down or sideways crops the right way up) — closes the v0.6 nits; a second tap on "Take a photo" while the permission dialog is up is ignored.
- Verified on the API 29 emulator for the camera path (`scripts/device-test.sh`), and in the release build (`scripts/device-test-release.sh`).
**Notes:** From the v0.6 demo (later list). Passed review on the first round (clamp, 1600 px minimum, EXIF and shot rotation, gallery routing and the second-tap guard each broken once and caught; both device scripts re-run green); merged; the camera ADR amended. Nits left: the crop reads the source file whole before a region decode (~15–25 MB for 50 MP); a non-JPEG/PNG/WebP/HEIF source falls back to a full decode (an OOM becomes the "unreadable" refusal); the preview can reach ~30 MB; turning the phone in the crop resets the framing (the shot survives).

- 2026-10-03 `assumed` A gallery photo goes through the same crop as a camera shot.
- 2026-10-03 `assumed` The book orders newest first, oldest first or by title (the catalogue's rating orders need the server); each view keeps its search, order and filters for the session.
- 2026-10-03 `decided` The export-after-fixing defect is fixed first in v0.8 (the user, at the v0.7 demo).
- 2026-10-03 `assumed` A recipe brought back from a file opens like a card opened for the first time: whatever the session held for that identity before (a deleted card's count, fixing, place) is forgotten.
- 2026-10-03 `assumed` An entry's ⋮ menu lists Export, then Delete (own) or Remove (found); it sits at the end of the title line, its label "Actions for “<title>”"; the entry opens its card everywhere but on the ⋮.
- 2026-10-03 `assumed` The crop: a fixed, centred 4:3 frame with a white border over the photo, which the author drags and pinches; outside the frame dimmed; it opens at the widest centred frame; "Retake" (camera) or "Cancel" (gallery) and "Done"; the title "Drag and pinch the photo to frame it".
- 2026-10-03 `assumed` The camera's viewfinder shows the whole frame that will be taken, letterboxed on a portrait phone, controls floating over it; an unreadable gallery file skips the crop so its refusal is said as before; a shot waiting in the crop survives turning the phone but not the end of the process.
- 2026-10-03 `decided` For now persisted-format changes need neither backward compatibility nor a migration of the owner's book: the owner is the only user and their phone holds test records only (the user). Revisit before any public release.
- 2026-10-03 `assumed` Book search matches a recipe when each query word begins a word somewhere in it — its title or any ingredient's name (labels in both languages, qualifier, free text) — so "плов кур" finds pilaf with chicken; FLOW-057's word-prefix match, not the server's analyser.
- 2026-10-03 `assumed` The view's header: a full-width search field ("Search by title or ingredient", ✕ to clear) and an order icon with "Newest first / Oldest first / By title"; oldest is the exact reverse of newest; by title puts untitled last; "Nothing found for “…”" with "Clear the search".
- 2026-10-03 `assumed` With no comparison factors in the shipped dictionary, an ingredient filter compares quantity per serving within one measure — mass in grams, volume in millilitres, any other unit only against itself — the measure most matching recipes hold (ties: mass, volume, piece); recipes outside it, without a serving count or with only "to taste" go last.
- 2026-10-03 `assumed` One ingredient filter at a time (with the entries below it in the dictionary), any number of tags; a funnel icon beside the order icon opens "Ingredient" (a field offering entries as the editor does) and "Tags" (checkboxes); chips under the search show the active filters with "Clear filters".
