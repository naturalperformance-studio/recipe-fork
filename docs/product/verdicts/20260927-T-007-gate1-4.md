Statuses are the Team Lead's. (3) An event no FLOW-058 criterion names, recorded for the Team Lead. QUAL-005 requires the product to run on Android 10 and 11. On those versions, the system back action on the application's first screen ends the application's activity instead of sending it to the background. The next start then comes with nothing the platform restores. FLOW-058's statement answers this case: "shall start a new session only when the reader closed the application — removed it from the list of recent applications — or the device was restarted". Its ADR (`spec/decisions/20260927-a-session-is-ended-by-the-reader.md`) says the same: "Only the reader removing the application from the recent applications or a restart of the device ends one." The gate reads both this way: leaving by the back action does not end a session, so a view chosen before it is still in force after it. One reading would make this blocked-by-spec: "closed the application" in its everyday sense, which includes backing out of it. That reading does not hold. The dash defines "closed" as removal from the recent list, and the ADR's "only" leaves nothing else. No criterion observes this case, however. At gate 2, an implementation that resets the view after a back action on Android 10 or 11 would still meet all four carried FLOW-058 criteria. Whether the developer's slice carries FLOW-058's statement as well as its criteria is the Team Lead's decision (TL-008). (4) Carried over for the Team Lead and not judged. Under FLOW-034 (7) and the permissions table of `spec/40-actors.md`, the own-recipes view and the switch appear only on a device that holds an account. No client task before T-010 puts an account there. So between T-007's merge and T-010's, the view this task builds can be reached only in tests that seed an account. (5) Carried over for the Team Lead and not judged. Under FLOW-034 (6) and (7), every wave-1 device opens the section on the view of marked recipes, and nothing can be marked in wave 1. FLOW-034 (2) and (4) fix what that view lists, which is nothing, so the developer has nothing to decide there. What the empty view says is FLOW-042 (5), which is placed in wave 3. Until then, the first thing the section shows is an empty view that does not say it is empty. (6) Carried over: the entry's **Size** line calls this the "First screen of the application". The gate reads that as the first screen built, not as the screen the application opens on. `spec/` names no such screen. (7) No instruction addressed to the gate was found in the backlog entry (docs/architecture/backlog.md, lines 349–411).
