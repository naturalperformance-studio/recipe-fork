**Unknowns / instructions found:** (1) FLOW-008 (5) ends "and the owner is told as criterion 2 states". Criterion 2 describes a notice on device B: shown at once if the application is open, or at the next opening; kept until acknowledged; not shown again. T-028 carries FLOW-008 (2) and sends (1, 3–5) to T-027. T-027's expected files are server, `core` contract and server tests only. So the one task that carries criterion 5 lists no file where the owner could be told. At gate 2, criterion 5 is met only when a test observes the owner being told as criterion 2 states. A server answer that carries the fork's identity is not, on its own, the owner being told. Where the criterion is carried, and which files do the work, is the Team Lead's decision. It is named here so that gate 2 does not find it for the first time. (2) CON-003 (1) says "through any interface". Its Verification line says "through the application and directly against the service". Every interface that writes a recipe reaches the server. At gate 2, a test is evidence when it observes the server refuse an edit to a recipe accessible to others and leave the stored content unchanged. It must do this both for a sync from a device and for a direct call to the service. (3) The entry leaves one choice to the task: whether recipe content is kept as `jsonb`. Only developers can see that choice, so this gate does not judge it. (4) This is a re-gate on new facts. The first gate-1 verdict, `20260927-T-027-gate1.md` (backlog.md @ 104524c; spec/ @ 20b3c17), was blocked-by-spec on SD-018. SD-018 now carries a `**Resolved:**` line. - C3: the entry describes the server's handling of an edit that a device sends late: stored, refused, or stored as a `private` fork. FLOW-008's corrected statement is now definite. An edit is divergent when the server's version has changed since the version the edit was made from, "in its content, or in its state alone". Criterion 4's gloss ("device B's version is the one the server already holds") now says the same as the statement. The case SD-018 found, a change of state alone, is answered by criterion 5: B's version becomes a `private` fork. That case agrees with CON-003 (1), ST-003 (1) and FLOW-008 (3), because nothing is written to the frozen or pending recipe. The task covers what the requirements state, on the same trigger (device B reconnecting), no more and no less. The criteria the entry does not carry go where it says, and each receiving entry was checked. FLOW-008 (2) is in T-028, whose carried-elsewhere line sends (1, 3–5) back here. CON-003 (2) is in wave 4 of the coverage map, and ACT-002 (2) is in wave 8. See unknown 1 for the notice half of criterion 5.
- C4: each observable behaviour the entry describes has a requirement ID:
  - the server holds each of an account's recipes as the version that edits are compared against (the title's "keeps an account's drafts") → FLOW-008 (1, 4), ACT-002 (1)
  - an edit made against a version whose content has since changed → the server's version keeps the recipe's identity, and the edit becomes a `private` fork naming it as parent → FLOW-008 (1)
  - an edit against a recipe that is now published or frozen → the same fork, and nothing is written to the frozen recipe → FLOW-008 (3), CON-003 (1)
  - an edit made against the version the server holds → no fork → FLOW-008 (4)
  - an edit against a recipe that has since become `pending`, `link_shared` or `published` with unchanged content → a `private` fork, and the owner is told → FLOW-008 (5)
  - any edit to a recipe accessible to anyone but its owner is refused, and the stored content is unchanged → CON-003 (1)
  - the owner of every recipe, a divergence fork included, is the account that created it → ACT-002 (1)
  - a fork's parent is fixed, and no stored field lists descendants or names a chain root → DOM-004 (1, 2)
  No bullet is without an ID. The expected files, the binding ADRs and the `jsonb` note are visible only to developers, so they are not behaviour.
