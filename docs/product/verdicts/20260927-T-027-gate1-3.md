The move settles unknown (1) of the second verdict. The notice that FLOW-008 (5) points at ("as criterion 2 states") is now in the same task as criterion 2. (2) The `pending` case now has no criterion in this task. FLOW-008's statement makes an edit divergent when the server's version changed "in its content, or in its state alone". This task's criterion 2 (FLOW-008 (3)) covers a state-only change only where the recipe is "published or otherwise frozen". The glossary defines "Frozen" as "no longer editable, by anyone, through any interface, permanently" (`spec/10-glossary/10-recipes-and-scaling.md:48`). ST-003's heading says freezing happens "at external visibility, not at submission". So `link_shared` and `published` are frozen, and `pending` is not, because withdrawing a submission makes the recipe editable again. The state table in `spec/60-entity-states.md` (lines 37–38) is looser: its submission rows say "recipe frozen". Either way, the behaviour is fixed. FLOW-008 (5) names `pending` explicitly, and ST-003 (1) refuses the edit. The two readings disagree only on which criterion is the evidence, so the product decision is not left open and no defect entry is owed. What follows for the gates: at T-027's gate 2, criterion 2 needs a test with a state-only change to `link_shared` or `published` that observes B's version become a `private` fork and nothing written to the recipe. A test with a content change alone is not enough. A state-only change to `pending` is not asked for by T-027's criteria. It is not an addition either, because FLOW-008's statement and criterion 5 cover it. At T-028's gate 2, FLOW-008 (5) is met only when a test observes B's version become a `private` fork naming the pending recipe as parent, and the owner being told. T-028's expected files are all on the device. Where the server half of that case is built is for the Team Lead to decide. It is named here so that T-028's gate 2 does not find it for the first time. (3) FLOW-008 (2) starts "when the server's answer reaches device B" and requires the owner to be told "a fork was created and why". The server's answer is defined by `RecipeContract.kt`, which is in this task's files and not in T-028's. Gate 1 does not judge what the answer carries, because a developer sees it and a user does not. It is named for the same reason as (2). (4) Carried over from the second verdict: CON-003 (1) says "through any interface", and its Verification says "through the application and directly against the service". At gate 2, a test counts as evidence when it observes the server refuse the edit and leave the stored content unchanged, both for a device's sync and for a direct call to the service. (5) The `jsonb` choice the entry leaves to the task is visible only to developers, so this gate does not judge it. No instruction addressed to the gate was found in the backlog entry (docs/architecture/backlog.md, lines 1452–1482).
