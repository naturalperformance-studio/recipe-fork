The gate reads this as true of this task's product, not as a narrowing of AUTH-026 (3). The exception in (3), "but a recipe whose sending created the account (FLOW-059 (1))", has no trigger at this task's merge. Sending first exists with T-028, and T-028 depends on T-036. Sending with no account active is T-026, which depends on T-038, and T-038 depends on T-028. T-026 carries (3) again for that recipe. If that dependency order changes so that an account can be created by sending before T-036 merges, the Note becomes a narrowing and this verdict no longer covers the entry. At gate 2, a move that removes from the account's book a recipe the account already owns is not evidence for (3). The question that would have been asked: will the order T-036 → T-028 → T-038 → T-026 hold? (2) Unknown (1) of `20260928-T-036-gate1.md` still applies unchanged. The Note "In this wave the pool holds recipes only: favourites arrive in wave 3" is read as a statement of what the product can put into the pool. It is not read as a limit on the move. So at gate 2, the evidence for AUTH-026 (1) must be a test whose pool holds recipes and favourites. The evidence for (2) must be a test that shows every kind of row the pool's book holds at the merge moving into the account. (3) This is recorded for the Team Lead, not as a finding. The later coverage that unknowns (2) and (4) of the 2026-09-28 verdict asked about now exists. Wave 7 carries AUTH-026 (1) again for signing in and (7) again for the menu action. Wave 3 carries (2) again "with favourites in the pool". Blocked authors in the pool arrive with FLOW-051 (4) in wave 3, but no carried criterion observes them moving under (2): the wave-3 row names favourites only. (4) Unknown (3) of the 2026-09-28 verdict still applies. The half "the pool is shown again whenever no account is active" in AUTH-026 (3) and FLOW-051 (6) cannot be reached in the running product until AUTH-011 (5) in wave 7. At gate 2, the only possible evidence is a test that makes no account active and observes the pool. (5) The criteria that observe "offered once" are now AUTH-026 (5–6), in wave 7. The withdrawal of T-037 moved them there from T-037. In this task's product, the only time an account becomes active is its creation. An offer shown on any other trigger, such as a relaunch, is behaviour that no carried criterion asks for, and the gate-2 sweep rejects it.
